# VMess 协议规范详解

> 基于 V2Ray 官方文档和 DeepWiki 整理
> 整理时间：2026-04-28

## 1. 协议概述

VMess 是 V2Ray 原创的加密传输协议，用于客户端与服务端之间的加密通信，设计目标是对抗深度包检测（DPI）。

### 核心特性

- **无状态协议**：每次数据传输独立，无需握手
- **基于 TCP**：所有数据通过 TCP 传输
- **UUID 认证**：使用 UUID 作为用户身份标识
- **时间依赖**：系统 UTC 时间误差需在 2 分钟内
- **加密传输**：支持多种加密套件
- **防重放**：基于时间窗口的会话 ID 去重
- **流量混淆**：随机填充、大小混淆、行为排空

## 2. 协议版本

- 当前版本：`1`

## 3. 消息格式

VMess 消息分为三个部分：**认证段**、**头部段**、**包体段**。

```
+-----------+-----------+-----------+
|  认证段   |  头部段   |  包体段   |
+-----------+-----------+-----------+
```

### 3.1 认证段

支持两种认证模式，服务端自动兼容检测：

#### AEAD 模式（推荐）

- 16 字节认证 ID，由用户账号的 `CmdKey()` 派生
- 使用 AES-128-GCM 实现认证加密
- 核心函数：`SealVMessAEADHeader()` / `OpenVMessAEADHeader()`

#### 遗留模式（已废弃）

- 16 字节认证值：`MD5(MD5(user.ID) | 时间戳)`
- 请求头采用 AES-128-CFB 加密
- 可通过环境变量 `v2ray.vmess.aead.forced=true` 强制禁用

#### 服务端检测逻辑

1. 优先尝试 AEAD 模式校验
2. 失败且未开启强制 AEAD 时 fallback 到遗留模式
3. 若开启强制 AEAD 则直接拒绝非 AEAD 连接

### 3.2 头部段（38 字节固定 + 可变长度）

| 偏移量 | 长度      | 字段说明                      |
|--------|-----------|-------------------------------|
| 0      | 1 字节    | 协议版本号                    |
| 1      | 16 字节   | 请求体加密 IV                 |
| 17     | 16 字节   | 请求体加密密钥                |
| 33     | 1 字节    | 响应头配置                    |
| 34     | 1 字节    | 安全类型 + 填充长度高位       |
| 35     | 1 字节    | 保留位                        |
| 36     | 1 字节    | 请求命令类型                  |
| 37     | 可变      | 目标地址 + 端口               |
| 可变   | 可变      | 随机填充字段                  |
| 末尾   | 4 字节    | FNV-1a 哈希校验值            |

#### 地址类型编码

| 类型 | 值  | 格式                                |
|------|-----|-------------------------------------|
| IPv4 | 1   | 4 字节 IP + 2 字节端口（大端序）   |
| IPv6 | 4   | 16 字节 IP + 2 字节端口（大端序）  |
| 域名 | 2   | 1 字节长度 + 域名 + 2 字节端口     |

#### 命令类型

| 命令 | 值  | 说明                                |
|------|-----|-------------------------------------|
| TCP  | 1   | 建立 TCP 连接                       |
| UDP  | 2   | UDP 包传输                          |
| MUX  | 3   | 多路复用连接                        |

### 3.3 包体段

根据请求头的 `Security`（加密类型）和 `Option`（扩展选项）采用不同封装。

#### 加密类型

| 类型                          | 值  | 实现方式                | 适用场景               |
|-------------------------------|-----|-------------------------|------------------------|
| `SecurityType_NONE`           | 0   | 明文传输                | 低安全需求             |
| `SecurityType_LEGACY`         | 1   | AES-128-CFB 流加密      | 兼容旧版（不推荐）     |
| `SecurityType_AES128_GCM`     | 2   | AES-128-GCM 认证加密    | 支持硬件加速（推荐）   |
| `SecurityType_CHACHA20_POLY1305` | 3   | ChaCha20-Poly1305    | 无 AES 硬件加速        |

#### 扩展选项（位掩码）

| 选项                          | 位  | 说明                     |
|-------------------------------|-----|--------------------------|
| `RequestOptionChunkStream`     | 1   | 开启分块传输             |
| `RequestOptionChunkMasking`    | 2   | 开启大小字段混淆         |
| `RequestOptionGlobalPadding`   | 4   | 开启全局随机填充         |
| `RequestOptionAuthenticatedLength` | 8   | 开启分块长度认证加密 |

## 4. 连接建立流程

### 4.1 客户端请求流程

```
1. 选择目标服务器 (serverPicker.PickServer)
2. 创建 ClientSession，初始化会话级密钥/IV
3. 调用 EncodeRequestHeader() 生成加密请求头
4. 调用 EncodeRequestBody() 配置请求体加密规则
5. 通过 buf.Copy() 进行双向数据传输
```

### 4.2 服务端处理流程

```
1. 读取并解密请求头 (DecodeRequestHeader)
2. 校验用户凭证 (TimedUserValidator.GetAEAD/Get)
3. 校验防重放 (SessionHistory.addIfNotExits)
4. 路由请求到目标地址 (dispatcher.Dispatch)
5. 加密响应数据并返回客户端
```

## 5. 安全机制

### 5.1 用户认证

- UUID 作为用户身份标识
- `TimedUserValidator` 基于时间窗口校验凭证有效性
- 时间窗口：默认 2 分钟

### 5.2 防重放机制

- 会话 ID = `用户UUID + 请求时间戳 + 随机IV`
- `SessionHistory` 缓存已处理会话 ID
- 缓存有效期：3 分钟
- 定期清理：每 30 秒清理过期记录
- 检测到大遗留模式重放攻击时，将对应遗留 ID 加入黑名单

### 5.3 加密方案选择

优先级：
1. AES-128-GCM（支持硬件加速）
2. ChaCha20-Poly1305（无硬件加速时）

### 5.4 抗流量分析

- **行为排空机制**：拒绝非法连接时模拟正常流量特征
- **大小混淆**：SHAKE-128 混淆编码
- **随机填充**：最大 64 字节全局填充
- **长度认证**：分块长度加密认证

## 6. 数据传输机制

### 6.1 分块传输

开启 `RequestOptionChunkStream` 后：

- **流模式（TCP）**：`[2字节大小][数据载荷]`
- **包模式（UDP）**：`[加密后的大小][AEAD加密的数据载荷]`

### 6.2 大小编码方式

| 编码方式            | 说明                               |
|---------------------|------------------------------------|
| 明文编码            | 2 字节大端序                      |
| SHAKE-128 混淆编码  | 大小与 SHAKE-128 流异或 + 随机填充|
| AEAD 加密编码       | 独立 AEAD 密钥加密大小字段         |

## 7. 动态命令系统

支持服务端向客户端下发动态配置命令（如 `CommandSwitchAccount` 切换账号）。

命令封装在响应头中，实现无断开重连的动态配置更新。
