# AI 代码生成约束指南

**项目**: vmess (io_uring + C++20 协程学习项目)  
**版本**: v1.0  
**日期**: 2026-04-30

---

## 一、核心原则

### 1.1 渐进式开发

```
❌ 禁止: 一次性生成大量代码
✅ 要求: 一点一点生成，每次只做一个小模块
```

**原因**: 这是一个学习项目，理解比速度更重要。

### 1.2 讨论优先

```
❌ 禁止: 直接写代码
✅ 要求: 先讨论 → 再写文档 → 最后生成少量代码
```

**流程**:
1. 用户提出需求
2. AI 分析需求，提出设计讨论
3. 用户确认/修改设计
4. AI 生成该模块的说明文档
5. 用户确认文档
6. AI 生成少量代码（不超过 100 行）
7. 用户测试/反馈
8. 循环

## 三、代码生成约束

### 3.1 单次代码量限制

| 类型 | 最大行数 | 说明 |
|------|----------|------|
| **头文件 (.hpp)** | ≤ 100 行 | 简洁的类/函数定义 |
| **实现文件 (.cpp)** | ≤ 80 行 | 具体实现 |
| **测试文件** | ≤ 50 行 | 单个测试用例 |
| **文档更新** | ≤ 30 行 | 增量更新 |

### 3.2 文件拆分原则

```
❌ 禁止: 一个文件塞满所有功能
✅ 要求: 按功能拆分成小文件
```

**示例**:

```
# ❌ 错误: 一个文件太大
include/vmess/coroutine/AllInOne.hpp  # 300 行

# ✅ 正确: 按功能拆分
include/vmess/coroutine/
├── Task.hpp         # 60 行
├── Awaiter.hpp      # 80 行
└── IoContext.hpp    # 70 行
```

### 3.3 代码复杂度限制

| 指标 | 最大值 | 说明 |
|------|--------|------|
| **函数长度** | ≤ 30 行 | 超过则拆分 |
| **类长度** | ≤ 100 行 | 超过则拆分 |
| **嵌套深度** | ≤ 3 层 | 超过则重构 |
| **参数个数** | ≤ 4 个 | 超过则封装为结构体 |

## 四、设计讨论模板

### 4.1 收到需求后的响应格式

```markdown
## 【设计讨论】{模块名称}

### 需求理解
简要复述用户的需求

### 设计方案
列出 2-3 个可选方案，每个方案包含：
- **方案名称**:
- **优点**:
- **缺点**:
- **适用场景**:

### 我的建议
推荐其中一个方案，并说明理由

### 待确认
列出需要用户确认的问题
1. ...
2. ...
```

### 4.2 方案示例

```markdown
## 【设计讨论】Async_operation Awaiter

### 需求理解
用户希望封装 io_uring 的异步操作，使其支持 co_await

### 设计方案

#### 方案 1: 结构体 + operator co_await
- **优点**: 代码简洁，符合 C++20 协程习惯
- **缺点**: 只能在局部作用域使用
- **适用场景**: 简单的异步操作

#### 方案 2: 类 + 成员函数 await_suspend
- **优点**: 可以保存状态，支持复杂操作
- **缺点**: 代码量稍多
- **适用场景**: 需要保存中间状态的异步操作

### 我的建议
推荐方案 1，因为 io_uring 的异步操作不需要保存中间状态

### 待确认
1. 你希望支持取消操作吗？
2. 你希望支持超时吗？
```

## 六、代码风格约束

### 6.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| **命名空间** | 全小写 | `vmess::coroutine` |
| **类名** | PascalCase | `class IoContext` |
| **函数名** | snake_case | `async_read` |
| **成员变量** | snake_case_ | `user_data_` |
| **常量** | kPascalCase | `kDefaultSize` |

### 6.2 注释要求

```cpp
// ✅ 推荐: 简洁的注释
// 获取 io_uring SQE
auto sqe = io_uring_get_sqe(uring);

// ❌ 禁止: 冗长的注释
// This function is used to get a submission queue entry from the io_uring instance
// which is required before we can submit any I/O operations to the kernel.
auto sqe = io_uring_get_sqe(uring);
```

### 6.3 头文件保护

```cpp
#pragma once  // ✅ 推荐
// 或
#ifndef VMESS_COROUTINE_TASK_HPP
#define VMESS_COROUTINE_TASK_HPP
// ...
#endif
```

```

✅ 要求: 每生成一个模块，立即生成对应的测试
```

```cpp
        executed = true;

    auto task = test_coro();
    // 协程尚未执行（initial_suspend）
    // ...
```

## 十、常见问题

### Q1: 什么时候可以生成大量代码？

**答**: 永远不行。这个项目的核心目标是学习，不是速度。

### Q2: 如果代码量超过限制怎么办？

**答**: 拆分成多个小模块，分多次讨论和生成。

### Q3: 如果用户没有反馈怎么办？

**答**: 等待用户的反馈，不要主动继续。

### Q4: 如果遇到 bug 怎么办？

**答**: 先分析问题，提出解决方案，和用户讨论后再修复。
